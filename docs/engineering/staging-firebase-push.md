## Sender contract and identity decision

The booking Worker calls the service binding `FCM_SENDER.fetch` at `POST https://fcm-sender.internal/send`. This is not a public endpoint. The new receiver accepts only the existing nine fields, real-package allowlist, staging environment, EN/AR locale, opaque IDs and a bounded token/body. The booking service still authorizes recipients and resolves current destination versions; the sender cannot decide who is a partner or owns a visit. It sends generic text, a replacement tag and the exact Android package restriction. Its reply contains only `accepted`, `invalid_token`, `failed` with a safe code, or `retry` with a safe code and optional bounded delay. Only a typed FCM 404 `UNREGISTERED` retires a token; the booking service fences that retirement by version. No payloads, credentials, destinations or provider bodies are logged.

### X.509 exchange under review

1. The sender posts to `https://sts.mtls.googleapis.com/v1/token` through `env.FCM_STS_CERT.fetch`. This Cloudflare mTLS binding presents the client certificate and proves possession of its key in TLS. The binding is used only for STS, the URL is fixed, and redirects fail. [Cloudflare mTLS binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/mtls/)
2. The STS JSON carries `subject_token_type` of `urn:ietf:params:oauth:token-type:mtls`, the pinned provider audience, and `subject_token` as a **string containing a JSON array**. Supply `FCM_STS_TRUST_CHAIN` as standard base64 DER strings in leaf-first order, followed by the issuing intermediate. The first entry must be the leaf used by the binding. Google holds the trust anchor in the provider configuration and verifies the chain, leaf match and certificate policy. The local adapter checks the list shape and base64 encoding. [Google X.509 exchange](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-x509-certificates)
3. The STS bearer has the `iam` OAuth scope and goes only to IAM Credentials `generateAccessToken` for `mawid-staging-fcm@mawid-development.iam.gserviceaccount.com`. The request has no delegates and asks for `firebase.messaging` for 600 seconds. The resulting bearer goes to FCM for `mawid-development`. The adapter refreshes in the last minute and retries minting once after an FCM 401. [IAM Credentials API](https://docs.cloud.google.com/iam/docs/reference/credentials/rest/v1/projects.serviceAccounts/generateAccessToken)

On compromise, remove the affected fingerprint promptly and use IAM to block sends if exposure is suspected. The CA keys stay in offline custody and the leaf key goes only into Cloudflare's certificate store.
